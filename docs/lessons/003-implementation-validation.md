# 实现和验证的经验

- 固件的默认无硬件配置成功编译不代表音频路径已经链接；必须额外构建开启音频、波束形成的配置并检查 codec/AEC 符号。
- 同一组线格式常量应以具体字节向量在服务器和固件分别验证，避免两边各自 round-trip 成功却互不兼容。
- WebSocket 控制和媒体必须分开排队，写入超时需要主动结束连接，不能等待下一个入站消息才处理慢消费者。
- FreeRTOS 的 task/queue/semphr 头依赖 FreeRTOS.h 的包含次序；自动排序 include 后应重新编译验证。
- 使用实际 DMA 播放参考可以覆盖限幅和欠载补零；声学延迟、麦克风时钟和双讲效果仍须硬件校准，编译或模拟器通过不能替代。
- 编码器峰值栈可能远大于普通任务。日志锁损坏可能是上游编码覆盖了堆，必须在每阶段检查内存并查库的栈要求，不能只修复报错位置。
- 模拟器宿主崩溃与固件断言应分别记录。拆分核心自测和依赖特定 DSP 执行环境的检查，跳过项必须显式输出，不能把部分通过写成完整音频验收。
