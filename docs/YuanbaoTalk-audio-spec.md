# YuanbaoTalk 音频处理规格

状态：v0.2 草案，2026-10-03。用户要求为 PTT 期间继续收听、默认按性能自动选择混音路数且允许手动设置、支持双麦 basic beamforming、noise suppression 和 AEC。目标硬件 ESP32-S3 / 16 MB PSRAM。本文仅设计，尚无硬件性能和音质验证。

## 1. 信号链与接口

建议逻辑链：双麦同步 PCM → 每麦 AEC → 固定方向基础波束形成 → 单声道 NS → Opus 编码。接收链为每源独立 Opus 解码 → 对齐与混音 → 音量/提示音/限幅 → 扬声器，同时从最终播放 PCM 分支提供 AEC 参考。

这是项目建议的逻辑顺序，具体库可能内部组合处理。若选用集成 AFE，应验证其实际处理图，不能叠加两套 AEC/NS 或随意调换顺序。网络保持单声道，不发送两路麦克风原始数据，不增加业务流数。

采集建议 16 kHz，双麦使用共同采样时钟，保持通道同步、增益和相位校准。不同外设时钟须有可验证的同步/漂移补偿。库的处理块长可能不等于 20 ms，使用有界适配缓冲接入网络帧，记录额外延迟；不把每块硬裁成 20 ms 丢采样。

年龄从该帧首采样实际采集时刻计算，包含前端、适配缓冲与编码等待；sample_index 在处理后单声道的连续采样时间轴上递增。算法延迟变化需更新时间映射，不重新编号已发流的采样。

## 2. 双麦基础波束形成与 NS

基础能力建议为固定朝向的延时求和：依据实际麦间距、朝向和通道校准配置相对延迟（必要时使用分数延迟），对齐后加权合成单声道。目标是改善预设说话方向的拾音，不承诺自动找人、追踪方向或区分所有侧后方声音。

硬件须在板型配置中记录两麦型号、间距、左右顺序、相对朝向、增益/延迟校准及预期嘴部位置。机壳开孔、手持遮挡和扬声器振动也需实测；未知布局不自动启用未经校准的 beamforming。

NS 对发送侧单声道降低背景噪声，提供开关和已验证强度档位；默认采用完成语音质量验收的保守档位。不以 VAD 门控代替降噪，PTT 期间即使被判断无声也维持协议规定的帧节奏，首版不启用 DTX。

乐鑫 AFE 是候选路径，其文档列出双麦 AEC、BSS、MISO 和 NS。BSS 是源分离，MISO 是多输入到单输出处理，不能仅因使用双麦就声称实现指定方向 beamforming。若采用 BSS 增强替代固定波束形成，须记录为不同模式，仍需满足基础波束形成的独立验收要求。[官方 AFE 说明](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/README.html)

此外，当前官方配置头注明双通道下 SE/BSS 可能优先于 NS，配置检查会修改冲突参数。因此实现阶段必须固定库版本并核对实际生效的算法，不能只检查两个开关均为 true。[官方配置定义](https://github.com/espressif/esp-sr/blob/master/include/esp32s3/esp_afe_config.h)

## 3. AEC 与 PTT 全双工

AEC 应选择适合语音通话且保留近端双讲的模式，不能把仅针对语音识别的远端抑制当成通话验收通过。两个麦克风的回声路径均须处理；候选为双通道 AEC 后再合成，实际库支持须在选型时验证。

参考必须对应实际扬声器输出，包含所有接收源、PLC、提示音、音量和限幅。参考取在最终数字处理后，按实际 DMA 播放时间对齐；发生欠载时，参考同步反映实际补零/重复策略。若 DAC 使用更高采样率，对参考进行同步重采样并补偿确定延迟。后级模拟增益变化也应通知 AEC，并控制功放失真；仅提供解码器输出不足以完整描述扬声器信号。

麦克风与播放时钟持续跟踪，补偿固定延迟和漂移。无播放时继续提供零参考。PTT 松开不上传麦克风音频，但建议保留本地 AEC 所需采集与参考运行，避免每次 PTT 冷启动；可按功耗另评估，不写录音存储。

按下 PTT 不静音、不自动压低别人音量。因负载不足先降低混音容量，不能自动关闭 AEC 来腾 CPU。硬件/算法无法达到最低一收一发与 AEC 时报告配置不支持；严重故障可明确暂停发送保护通话，不把它作为正常半双工降级模式。

AEC 处理本机已知播放参考的声学回声；邻近其他设备发出的声音不一定有相同且可用的参考，仍需单独进行多机同室测试，不能承诺任意部署都无啸叫。

## 4. 混音容量自动选择和手动设置

定义 `N_verified` 为当前板型、CPU 频率、软件/算法版本和音频配置实测的安全并发解码上限，`N_effective` 为当前可播放路数。设置提供“自动（默认）”和“手动 1..N_verified”，保存用户选择，显示当前实际路数与过载降级原因。4 路仅为基准测试档位，性能允许时可以更多。

自动选择依据完整链路的验证配置与运行数据：始终预留双麦前端、AEC/NS/波束形成、一路发送编码、无线中继、服务器双链路和系统余量。不能只看芯片型号、PSRAM 容量、当前活跃人数或平均 CPU 利用率，也不能闲时选高档后按 PTT 才发现过载。

首版建议随固件提供各板型经验证的能力表，启动时按实际频率、内存、算法配置选档；变更配置后重新选档。没有匹配能力表时从 1 路保守试运行并标记未验证，完成完整负载测量后才公布更高上限；连 1 路也不满足时判定配置不支持。没有用模拟/回放负载证实剩余能力时，不能因为目前只收到一人就自动宣称可收八人。

运行监测包括每处理块截止期、任务最坏/P99 耗时、各核余量、采集/播放欠载、解码队列和内部 RAM/PSRAM。建议验收预留至少 25% 实时处理余量；具体以任务调度和连续运行验证，不能简单相加各核百分比。

自动模式建议连续 1 秒存在计算性欠载/超期或余量不足时降一档；严重计算超期可立即降档。仅网络丢包不触发 CPU 容量降档。恢复必须至少连续 30 秒稳定且测量证实下一档余量，在流加入或非 PTT 期间逐档恢复；不是每帧增减。阈值为待实测建议。

手动模式通常固定用户目标；越过已验证上限时设置失败并解释原因，不保存无效配置。运行出现超期时仍允许紧急保护性降档，保留用户目标、明确提示实际路数，并按稳定窗口恢复；不能静默破坏实时播放或关闭 AEC。音频前端配置变化若降低可用上限，显示原目标暂不可用。

改变 N 时按共同协议稳定保留优先流并淡入淡出，增益平滑变更，AEC 参考自然跟随最终输出。容量只决定本机解码/播放，不减少无线和服务器转发源数；减混音路数不等于减少网络负载。

## 5. 验收与待定项

- 双讲：近端与远端同时讲话，PTT 期间持续听到对方，检查近端语音被误消除、残余回声和啸叫。
- AEC：分别测远端单讲残余回声、近端单讲失真、双讲语音保真、音量变化、提示音、混音容量变化和播放欠载后的恢复。ERLE 等指标只在适当场景解释，不把单讲高抑制量等同于双讲质量。
- 双麦：固定目标方向与侧向噪声，对比同音量的单麦基线；测试近距离嘴部、转动、手持遮挡、失配和单麦故障。目标指标由板型原型实测后冻结。
- NS：稳定噪声、突发噪声和多人声环境，检查清晰度、辅音损伤、金属音和延迟。
- 性能：1、2、4 及更高候选路数，完整前端+编码+中继+服务器共存，持续运行并记录最坏延迟、丢帧、欠载和内存；无实测不承诺 S3 同时完成所有功能时仍达 4 路。
- 设置：自动/手动、重启持久化、算法配置变化、过载下降和恢复、服务器能力上报；确认网关仍转发未选中的流。

下一步需要确定实际双麦接口、间距/朝向和扬声器布局，选择并固定 ESP-IDF 与音频算法版本。当前不编写代码、不执行板上校准、不声称音质或并发性能已通过。
