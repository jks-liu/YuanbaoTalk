# Spec 关键修改

## 2026-10-04：发布版本脚本

- 新增 tools/version-bump.py，支持默认 patch、minor、major、明确版本、只读 current 与可选固件构建，复用 Python 和现有 ESP-IDF 构建入口。
- 初始化固件 version.txt 和服务器 __version__ 为 0.1.0；同步前验证一致性，避免误改协议和依赖版本。
- 固件 CMake 显式跟踪版本文件，确保已有构建目录首次接入版本管理时重新配置。
- 新增临时目录自动测试和 README 用法，说明构建失败后保留版本及重试方式。
- 验证：6 项脚本测试、Ruff 检查及 Windows ESP-IDF 6.1 实际构建通过；构建元数据和二进制应用描述版本均确认为 0.1.0。

## 2026-10-03：实现固件与服务器

- 按后续授权新增 ESP-IDF 6.1 固件、Python 转发服务器及构建/测试脚本，硬件未选型按可配置标准 I2S 实现。
- 实现原始流透明转发、独立出口去重、防服务器回灌、频道/绑定隔离、流准入、过期队列与慢消费者关闭。
- 补齐控制响应缓存 640 硬上限及 MEDIA_REBIND，解决请求速率与 30 秒缓存保护期冲突、单次令牌无法重绑的问题。
- 实现 PTT 全双工、双麦 AEC/基础波束形成/NS、混音与降档；未经板型验证时默认混音上限为 1，不以 PSRAM 容量承诺性能。
- 修复 Opus 栈不足导致的堆损坏；48 KB 音频栈、运行栈余量日志及堆检查用于后续验收。丢包使用 PCM 重复渐弱，不错误调用 NULL 输入解码。
- QEMU 中 AEC 处理导致宿主崩溃，单独保留 AEC/NS 自测配置并明确未验证，详见 issues/009。

## 2026-10-03：PTT 全双工与可变混音容量

- 用户确认 PTT 期间继续收听，移除按 PTT 关闭扬声器的建议；新增双麦基础波束形成、NS、AEC 的音频规格与双讲验收。
- 混音由固定四路改为默认自动/可手动设置，定义完整负载下验证上限、过载保护、恢复滞回和设置持久化；四路保留为测试档。
- 同步协议选流、可变增益、HELLO 能力和能力更新消息；服务器不因网关混音容量而过滤下游需要的流。
- 补充最终播放 PCM 的 AEC 参考、采集同步、前端延迟计龄以及 BSS/NS 配置兼容性。核对官方 AFE 文档，具体算法和性能仍须实测。
- 解释 TTL=3 是源发送+两个中继的建议初值，保留 1–16 设置；明确密集网络低 TTL 仍可能拥塞，稀疏长链可提高但需验证。
- 更新问题、经验与交接进度，仍仅修改文档。

## 2026-10-02：协议评审与 v0.1 草案

- 扩展固件与服务器概述，新增共同协议，集中定义两端必须一致的包字段和时序，避免分别实现后无法互通。
- 根据用户确认采用 ESP32-S3 / 16 MB PSRAM、PTT、最多 4 路远端混音、设备自动网关、首版无需加密。
- 明确逐源转发、终端混音，服务器只做并发容量准入；本地发言不依赖公网许可。
- 区分业务频道与无线信道，统一数字/UUID 编码并避免命名冲突；补充 AP 同信道约束。
- 定义 64 字节消息头、原始身份、序号、采样位置、自描述 AUDIO、END 排空与超时；候选音频为 20 ms Opus。
- 定义 TTL 的逐发送语义、滑动窗口、独立出口状态和 via_server 防回灌，补齐自动多网关处理次序。
- 明确控制/媒体连接、订阅绑定、代理流注册、容量拒绝、断网恢复和截止时间，避免无限积压和旧音频补播。
- 补充多路混音选流、限幅、时钟漂移、声学回声边界；4 路性能须实测。
- 增加容量估算、场景验收、资料来源、问题与经验记录。参数为草案，没有编写程序或运行硬件测试。
