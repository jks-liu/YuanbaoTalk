# 实机联调与验收

当前没有已选板型或实机结果。以下步骤是待执行验收，不代表已通过。软件构建/核心自测结果见 `implementation-progress.md`。

## 1. 板级配置

记录模组型号、Flash/PSRAM、双麦和功放型号、所有 GPIO、I2S 格式、麦间距/朝向与供电。按 README 填配置；需要 I2C 初始化的 codec 应先实现对应板级适配。确认数字采样的有效位位置和左右声道，不把示例 GPIO 用作默认板型。

先用支持的真实 S3 执行 `-Afe` 算法冒烟自测，检查 AEC/NS 是否正常、堆完整性及剩余栈；该自测不启动 I2S。QEMU 宿主崩溃仍需另行定位，不能以编译成功代替此步。

## 2. 音频基线

- 16 kHz 共时钟双麦，核对振幅、极性、同步和无丢样。波束形成先关闭。
- 检查实际播放 DMA 参考：音量变化、限幅及播放欠载补零均对应扬声器数据；校准 `YT_AEC_REFERENCE_DELAY`。
- 先跑一收一发加两路 AEC/NS。PTT 持续发送时另一台讲话应持续播放，松键结束，60 秒超时后须松开重按。
- 测远端单讲、本地单讲和双方同时讲话，观察残余回声、近端语音被抑制程度及啸叫。不能仅凭零输入冒烟检查判断 AEC 音质。
- 校准双麦增益与 Q8 延迟，比较目标方向、侧向噪声及反向目标；检查 AEC 后两个通道相位关系。必要时按实测调整算法顺序。

## 3. 转发拓扑

至少三台设备，记录空口抓包和串口状态。先断开服务器验证直连/一跳/两跳中继，TTL=1/2/3 分别限制发送次数；再让两台以上成为在线网关。

- 同源经多个网关上传只下发一次；服务器下行的无线后继不能再次上传；本机不播放自身源。
- 同频道跨不同固定 AP 无线信道互通；不同业务频道隔离。
- 断开一个网关，另一个代理继续；断开服务器，本地继续；恢复后只转发新音频。
- 多源同时讲话时按设备容量稳定选流；本机降档不减少网关为下游转发的源。
- 校验 END 先到、START 丢失、乱序、窗口外旧包、队列拥塞、媒体重绑和频道切换，无旧语音补播。

## 4. 性能与容量

保持真实双麦/AEC/NS、PTT 编码、混音、ESP-NOW 和在线网关全部开启，依次验证 1/2/4/更多路。记录处理平均/峰值耗时、栈最低剩余、内部堆、I2S 溢出/欠载、掉帧和麦到扬声器延迟，至少覆盖长时运行与弱网。

只有完成该负载验收后才能提高 `YT_VERIFIED_MIX_MAX`。自动模式在验证上限内降档/稳定恢复，手动模式仍受过载保护。采集溢出触发暂停发送直到重启，必须记录并解决其负载或时钟原因，不能把频繁重启当作正常工作流程。
