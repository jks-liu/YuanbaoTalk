# 控制重试缓存和媒体重绑的协议补全

实现时发现两处草案不够具体：每秒 20 请求与“128 条响应至少保存 30 秒”不能同时用固定 128 槽满足；媒体令牌一次性使用后也没有定义如何重新获取。

处理：每会话响应缓存保留至少 128 条及最近 30 秒，硬上限 640 条，达到上限返回 RATE_LIMIT，过期旧 request_id 不再执行。新增 MEDIA_REBIND 请求返回新的单次媒体令牌；有效 BIND 才替换旧媒体连接，LEAVE/换订阅使旧令牌失效。

固件目前采用控制与媒体一起重连重新 JOIN 的方式恢复，服务器同时支持单独媒体重绑。多网关的原始流身份不会因连接重建改变，旧音频不补传。
