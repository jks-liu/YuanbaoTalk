# 音频栈不足与模拟器 AEC 执行失败

## 现象与定位

S3 自测最初在 Opus 后的日志锁、AEC 初始化锁处断言。逐次加入堆完整性检查，确认堆损坏发生在首次 Opus 编码后，初始化前后均正常。

固定依赖 esp_audio_codec 2.6.2 的 README 提示编码器运行栈约需 40 KB；原自测沿用 8 KB main_task，音频任务也只有 16 KB。改用独立 48 KB 自测任务和 48 KB 音频任务后，Opus 编解码及堆检查通过；音频初始化也移入该任务，DMA 启动时消费者已存在。保留检查与栈最低剩余量日志，不把异常误归因于 IDF 6.1 的 libc。

另一个独立问题是 Opus 包装接口不接受 NULL 输入，不能仅设置通用 PLC 枚举就调用。当前采用上一 PCM 块重复并在 120 ms 内线性衰减的基础丢包掩蔽，初始无历史则补零；不冒充 Opus 内建 PLC。

## 尚待验证

安装的 Windows QEMU esp_develop_9.2.2_20260417 在 AEC 创建成功后的 aec_process 中直接退出，宿主退出码 3221225477（0xC0000005），没有固件 panic 回溯。不能据此认定 AEC 在真实 S3 上可用或不可用，也未证明具体模拟器指令缺陷。

核心自测默认不执行 AEC/NS，并明确打印 NOT TESTED；`build-selftest.ps1 -Afe` 构建保留完整 AEC/NS 冒烟检查的独立镜像。实机或修复后的模拟器需继续运行该检查，以及真实声学双讲验收。实际音频前端中的 AEC/NS 未关闭。
