# TTL 无法独自解决中继和服务器回环

原始 spec 仅提出 TTL=16 和“适当方法防止环路”。TTL 能限制传播长度，但同一帧仍会沿多路径重复播放/转发；自动网关可能把服务器下行再次上传，服务器重置 TTL 后形成跨网络循环。

处理：固定原始流身份和逐消息序号；每流滑动窗口去重；播放、无线发送、服务器上传分别记录 pending/sent 状态；服务器下行设置不可清除的 via_server 标志，禁止再次上传。只有服务器首次进入目标无线段时可重新分配无线预算。

精确定义 TTL 包含下一次发送：预算 1 发出的包携带 0，接收者可以播放或上传，不能无线续传。默认建议 3，最大 16，避免把上限当作部署默认。

状态：共同协议已定义，覆盖菱形、环形、两地各双网关和不同入口到达次序。首版有界泛洪不保证最短路径和理论最大覆盖，未来保证覆盖需显式路由。
